1. 내가 만든 1안이 무엇이고 어떤 결과를 냈는가
2. 공개된 상위권 팀(1위, 3위)의 모델링을 확인해 본 장단점
3. 같은 조건으로 직접 비교한 숫자와, 거기서 나온 개선 사항

## 요약

- 최종 private 점수는 우리 팀 **0.62**, 1위 팀 **0.63**이었습니다. 차이 0.01은 private 크기(1,131샷)의 표본 흔들림(SD 약 0.037)보다 작아서, 이 점수만으로 어느 모델이 더 낫다고 말할 수 없습니다.
- 1위 팀의 최종 제출 모델은 공개 저장소의 `main.py` 기준으로 **입력 21개를 그대로 쓴 랜덤포레스트 하나**였고, 3위 팀은 **KNN 하나**(입력 21개)였습니다. 반면 내 1안은 랜덤포레스트 + ExtraTrees + 두 단계 모델을 섞고 입력을 65개로 늘린 **가장 복잡한 구성**이었습니다.
- 같은 검증으로 직접 재 보니, 리더보드와 비슷한 **무작위 분할에서는 1안이 가장 높았고**(0.570), **처음 보는 입력에서는 입력 21개 랜덤포레스트가 더 높았습니다**(0.292 대 0.254). 복잡하게 만든 이득은 "같은 입력이 학습에 있는 샷"에서만 나타났습니다.
- 개선의 핵심은 **더 복잡한 모델이 아니라 순서와 기준**입니다. 단순한 기준선을 먼저 세우고, 추가하는 것마다 흔들림과 비교하고, 선택 기준을 점수 공개 전에 정해 두는 것입니다.

## 1. 내가 한 일: 1안 전처리와 모델링

### 전처리

| 문제 | 확인한 값 | 처리 |
|---|---|---|
| 쓸 수 없는 열 | 식별 열 3개(shot_id·id·Shot), 값이 하나뿐인 열 8개 | 제거. 입력 21개 + 표시 열 4개 = 25개 |
| 결측 | 공장 온도·습도 90행(두 덩어리) | 결측 덩어리 앞뒤 실측 30개씩의 중앙값으로 채우고 결측 표시 열 추가 |
| 이상한 값 | 속도 0, 긴 사이클 등 | 지우지 않고 표시 열만 추가(지워도 점수 차가 표준편차 안쪽) |
| 입력이 같은 행(쌍둥이) | 입력 21개가 앞 행과 같은 행 3,174개(42%), 같은 묶음 안 라벨 일치 97.8% | 행은 유지하고, 묶음 번호는 **검증 분할에만** 사용 |
| 클래스 불균형 | 정상 77.6% | 클래스 가중치(balanced의 0.5제곱), 정확도 대신 macro F1 |

### 모델(1안)

랜덤포레스트와 ExtraTrees(각 900그루)의 확률 평균, "불량인가 → 어떤 불량인가" 두 단계 모델을 반씩 섞고, **앞뒤 이벤트의 입력값 40개**를 추가했습니다(입력 25 → 65개). 정답에서 나온 값은 쓰지 않았습니다. `python main.py` 한 줄로 약 80초에 재현됩니다.

### 결과

| 평가 | 1안 |
|---|---|
| 중간 리더보드(public) | 0.5987 (공개 기준선 0.2517) |
| 최종 private | 0.62 |
| 처음 보는 입력(쌍둥이 묶음 검증) | F1 0.258, 불량 탐지율 10.3% |
| 새 생산 구간(연속 100샷) | F1 0.136, 탐지율 1.2% |

내부 비교에서 일관된 이득을 준 것은 앞뒤 입력값 추가(+0.0045) 하나였고, 클래스 가중치·잎 크기·나무 수 등 20여 가지는 모두 시드 흔들림(±0.005) 안이었습니다. 당시에는 이를 "1안이 평평한 정점"이라고 해석했습니다.

## 2. 상위권 팀 확인: 장단점

공개된 자료(1위 팀의 노트북·`main.py`, 3위 팀의 보고서·`main.py`)를 직접 읽고 정리했습니다. 코드를 가져온 것은 아니고, 무엇을 어떻게 했는지만 확인했습니다. 두 팀의 최종 제출 파일이 저장소에 여러 개 있는 경우가 있어, 아래 모델은 `main.py`에 적힌 설정을 기준으로 했습니다.

### 1위 팀 (private 0.63)

| 항목 | 내용 |
|---|---|
| 모델 | 랜덤포레스트 300그루, 클래스 가중치 강도 p=0.6, 입력 21개, 결측은 학습 중앙값 |
| 특징 | 이상치는 지우지 않음, 중복 행도 지우지 않음, 입력 21개 외에 만든 열 없음 |
| 선택 방식 | p를 6가지 값 × 시드 5개 × 3가지 분할로 비교해 "무난한 값" 0.6 선택. 선택을 내부 검증으로 했다고 명시하고 public 점수로 고르지 않았다고 적음 |
| 그 밖 | MLP를 시드 5개 평균 ± 표준편차로 체계적으로 비교, 비용표·구간별 불량률·학습곡선까지 수행 |

**장점**
- 가장 단순한 구성이라 설명과 재현이 쉽고, 같은 조건으로 `python main.py` 한 줄이 돌아갑니다.
- 모든 표가 시드 5개 평균 ± 표준편차이고, 선택 기준(내부 검증, public 불사용)을 문서에 미리 적어 두었습니다.
- 쌍둥이 문제(검증 샷의 48%가 학습에 같은 입력, 평가 구간의 58%)를 정확히 짚고 시간순 분할을 함께 잰 점이 우리 분석과 같은 결론입니다.

**단점·위험**
- 앞뒤 샷 정보나 파생 변수를 쓰지 않아 입력 정보량이 가장 적습니다.
- 노트북에서 만든 제출 파일은 p=0.5, `main.py`는 p=0.6이라 **같은 저장소 안에서 설정이 어긋나** 있습니다. 어느 파일이 최종인지 저장소만으로는 확인되지 않습니다.
- 시간순 검증에서는 정상과 Short_Shot 외 불량을 거의 못 맞힌다고 스스로 적었습니다. 즉 점수의 큰 부분이 같은 입력을 외우는 데서 나옵니다.

### 3위 팀

| 항목 | 내용 |
|---|---|
| 모델 | KNN(이웃 15개, 맨해튼 거리, 거리 가중, MinMax), 입력 21개, 클래스 가중치 없음 |
| 선택 방식 | 이웃 수·거리·가중·스케일러 84개 조합을 5분할 × 3회로 비교. 같은 데이터로 고른 점수라 낙관적일 수 있다고 명시 |
| 공개 점수 | public 0.5890 (보고서 기준) |
| 그 밖 | 불균형 대응 6가지(SMOTE, 판정 배율 등)를 모두 시험해 **모두 기각**, 처음 0.58로 보인 값을 중첩 검증으로 다시 재서 0.546으로 정정, AI 코드 오류 3건을 직접 찾아 고침 |

**장점**
- "값이 똑같은 학습 샷의 정답을 그대로 가져온다"는 KNN의 성질이 이 데이터의 쌍둥이 구조와 맞아서, 가장 단순한 모델로 public 0.589를 냈습니다.
- 검증의 함정을 잘 찾았습니다. 낙관적 점수를 중첩 검증으로 바로잡고, 시간순 점수가 3개 클래스만으로 평균된 것도 7개 기준으로 다시 계산했습니다.
- 어떤 방법을 왜 기각했는지가 표로 남아 있어 재검토가 쉽습니다.

**단점·위험**
- 쌍둥이를 묶고 재면 0.268로 떨어지고, 시간순에서는 0.138(불량 231건 중 45건 탐지)입니다. 새 입력에 대한 일반화 능력이 약합니다.
- 설정을 고른 데이터와 점수를 잰 데이터가 같습니다(스스로 한계로 기록).
- 확률 출력이 거칠어서(이웃 15개의 가중 투표) 경보 기준을 세밀하게 옮기기 어렵습니다.

## 3. 같은 조건으로 직접 비교

**방법**: 학습 5,274샷에서 같은 5분할을 시드 7·123·2026으로 세 번(총 15번) 돌려 7개 클래스 macro F1의 평균 ± fold별 표준편차를 구했습니다. "새 입력"은 쌍둥이를 같은 쪽에 두는 분할이고, "무작위"는 쌍둥이가 갈라질 수 있어 리더보드와 비슷한 구조입니다. 3위 팀 KNN을 같은 틀에서 돌린 값(새 입력 0.268, 무작위 0.563)은 그 팀 보고서의 값(0.268, 0.562)과 거의 일치해서, 이 비교 틀이 맞게 만들어졌다는 점검이 됩니다.

| 구성 | 입력 수 | 새 입력(쌍둥이 묶음) | 무작위 5분할 |
|---|---|---|---|
| 1위 팀 방식: RF, p=0.6 | 21 | 0.292 ± 0.021 | 0.540 ± 0.040 |
| 전처리만 우리 것 + RF, p=0.6 | 25 | 0.295 ± 0.017 | 0.539 ± 0.040 |
| 우리 E안: RF, p=0.5 | 25 | 0.293 ± 0.023 | 0.546 ± 0.039 |
| RF + 앞뒤 입력 40개 | 65 | 0.299 ± 0.025 | 0.561 ± 0.034 |
| **우리 1안**: RF·ET·두 단계 | 65 | **0.254 ± 0.022** | **0.570 ± 0.041** |
| 3위 팀 방식: KNN | 21 | 0.268 ± 0.034 | 0.563 ± 0.044 |
| RF + KNN 확률 평균 | 21 | 0.283 ± 0.025 | 0.566 ± 0.042 |

읽는 법과 확인된 것:

1. **전처리와 클래스 가중치 차이는 거의 영향이 없었습니다.** 새 입력 기준 0.292, 0.295, 0.293으로 세 구성의 차이가 0.003 이내입니다(fold별 표준편차는 0.02 안팎). 1위 팀의 단순한 전처리와 우리의 정교한 전처리는 점수로는 구분되지 않았습니다.
2. **무작위 분할에서는 1안이 가장 높습니다**(0.570). 입력을 늘린 RF(0.561)와 KNN(0.563)도 같은 수준이라, 최상위 구성들 사이 차이는 0.01 안쪽이고 fold별 표준편차(0.03~0.04)보다 작습니다. 이 조건에서 모델들을 구분하기는 어렵습니다.
3. **처음 보는 입력에서는 순서가 뒤집힙니다.** 입력 21개 RF가 0.292, 1안이 0.254로, 1안이 가장 낮습니다. 복잡한 구성의 이득이 "같은 입력이 학습에 있는 샷"에 몰려 있다는 뜻입니다.
4. **RF와 KNN을 섞어도 이득이 없었습니다.** 혼합(0.283 / 0.566)은 두 모델 각각의 중간값이고, 어느 조건에서도 둘 중 더 나은 쪽을 넘지 못했습니다.

(숫자는 학습 데이터 안에서 잰 것이며, 시드 3개 × 5분할의 평균입니다. 모델 쌍마다 짝지은 검정은 하지 않았습니다.)

## 4. 해석: 왜 복잡한 1안이 단순한 모델과 비슷했나

- 최종 평가 구간의 약 58%가 학습에 같은 입력을 가지고 있어서(1위·3위 팀 보고서와 우리 분석이 모두 같은 값을 확인), 점수의 큰 부분이 **외워서 맞히는 능력**에서 나옵니다. 이 능력은 랜덤포레스트 하나, KNN 하나로도 이미 충분히 갖춰집니다.
- 우리 1안에서 새로 더한 요소(ExtraTrees 혼합, 두 단계 모델, 앞뒤 입력)는 내부 검증에서 +0.005 안쪽이거나 일관되지 않았고, 이를 "평평한 정점"이라고만 해석했습니다. 지금 보면 **더 단순한 모델이 같은 수준이라는 신호**이기도 했습니다.
- 그래서 0.62 대 0.63의 차이(0.01)는 모델의 우열이라기보다 표본 흔들림 범위로 보는 것이 맞습니다. 순위를 예측하거나 설명하는 근거로 쓰지는 않습니다.

## 5. 개선 사항

근거가 확인된 정도를 함께 적었습니다. "확인"은 위 표나 상대 팀 보고서에서 숫자로 본 것, "추정"은 아직 직접 재 보지 않은 것입니다.

| 순위 | 개선 사항 | 근거 | 확인 정도 |
|---|---|---|---|
| 1 | **단순한 기준선(입력 21개 RF, p 조정)을 먼저 세우고**, 추가하는 요소마다 같은 검증에서 흔들림과 비교한 뒤에만 채택 | 단순 RF가 새 입력에서 1안보다 높았음(0.292 대 0.254), 전처리·가중치 차이는 0.003 이내 | 확인 |
| 2 | **모델 선택 기준을 점수 공개 전에 정해 두기**(쌍둥이 묶음 + 무작위 검증을 함께 보고, public은 확인용으로만) | 1위·3위 팀 모두 선택을 내부 검증으로 했다고 명시. 우리는 public 0.5987 대 0.5710으로 1안을 골랐는데, 이 차이는 표본 흔들림(SD 0.037) 안쪽이었음 | 확인(상대 팀 방식은 문서 기준) |
| 3 | **설정을 고른 데이터와 점수를 재는 데이터를 분리**(중첩 검증) | 3위 팀이 0.58로 보였던 값을 중첩 검증으로 0.546으로 정정함 | 상대 팀 보고 |
| 4 | **앞뒤 입력(40개)의 효과를 따로 재검토**. RF에서는 새 입력 +0.006(0.293→0.299)으로 표준편차 안쪽이고, 뒤 사건 입력은 실시간에서 쓸 수 없는 제약도 있음. 실시간용은 앞 사건만 쓰는 변형이 필요 | 위 표 | 확인(효과 크기), 추정(재검토 후 채택 여부) |
| 5 | **파생 변수(이슬점·건조도)를 따로 시험**. 3위 팀이 RF에서 쌍둥이 묶음 검증 +0.019를 보고했으나 KNN에서는 효과가 일정하지 않았음. 우리는 아직 시험하지 않았으므로, 우리 틀에서 확인되면 점수가 더 오를 것으로 사료된다 | 3위 팀 보고서 | 추정 |
| 6 | **저장소 정리**: 최종 제출 파일과 `main.py` 설정이 어긋나지 않게 하나로 고정(1위 팀 저장소에서 p=0.5와 0.6이 섞여 있던 것을 반면교사로) | 1위 팀 노트북 대 `main.py` | 확인 |
| 7 | **새 정보를 기록**: 같은 시기의 데이터를 늘려도 시간순 점수가 오르지 않았음(0.136→0.141, 3위 팀 보고). 금형 온도 같은 지금 재지 않는 값과, 설정을 바꾼 다른 시기의 기록이 필요 | 3위 팀 보고, 우리 학습곡선 | 상대 팀 보고 + 확인 |

해 보았지만 이득이 없었던 것: 랜덤포레스트와 KNN의 확률 평균(3절 4번 항목).

## 6. 한계와 주의

- 상대 팀의 숫자와 설정은 **공개된 문서와 코드를 읽고 정리한 것**이며, 팀 내부 사정(실제 제출 파일 선택 과정 등)은 모릅니다. 1위 팀의 최종 제출 모델은 저장소의 `main.py` 기준으로 정리했고, 어느 제출 파일이 0.63을 받았는지는 확인하지 못했습니다.
- 3위 팀의 private 점수는 확인하지 못해서 적지 않았습니다.
- 직접 비교한 숫자는 학습 데이터 안의 검증입니다. 최종 private 점수와 같지 않고, 점수를 예측하는 용도가 아닙니다.
- 시간순 분할 숫자는 이번 비교에서 뺐습니다(점수 계산 방식에 따라 값이 크게 달라져 팀 보고서의 값과 직접 비교할 수 없습니다).
- 실험 코드는 개인적으로 돌린 일회성 스크립트이며 팀 저장소의 `main.py`는 바꾸지 않았습니다.

## 7. 정리: 다음에 다르게 할 것

1. 시작은 입력 21개 랜덤포레스트 하나로 한다.
2. 검증은 쌍둥이 묶음과 무작위를 함께 본다. 점수는 평균과 흔들림을 같이 적는다.
3. 요소를 하나 더할 때마다 "흔들림보다 큰가, 새 입력에서도 오르는가"를 확인한다.
4. 선택 기준은 제출 전에 문서로 먼저 고정한다.
5. 그러고 나서 새 측정이나 파생 변수처럼 정보를 늘리는 쪽에 시간을 쓴다.

## 부록. 프로젝트 개요와 재현 방법

포스코 K-뉴딜아카데미 딥러닝 1기 최종 프로젝트입니다. 샷마다 남는 공정·센서 기록(7,535샷 × 32열)만으로 불량 유형 7종(정상, Short_Shot, Blow_Hole, Exfoliation, Stain, Deformation, 기타불량)을 미리 예측하고, 지표는 macro F1입니다.

- 최종 제출안(1안): 랜덤포레스트 + ExtraTrees 확률 평균 + 두 단계(불량 여부 → 불량 종류) 혼합 + 앞뒤 사건 입력 40개 추가. 중간 리더보드(public) **0.5987**, 최종 private 0.62.
- 현장성을 높인 또 다른 안(2안): 랜덤포레스트 2개 평균, 입력 25개. 중간 리더보드(public) 0.5710.
